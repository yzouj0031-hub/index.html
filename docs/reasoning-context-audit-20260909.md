# 2026-09-09 对局推理与上下文修复

## 找到的实际问题

### 1. 原生 Claude / Gemini 请求漏传本人的系统记忆

原生 Anthropic / Gemini 请求组装先过滤了所有 system 消息，
再仅取第一条作为系统提示词。因此玩家自己的后续 system 记忆会被丢弃。
例如守卫收到的同守同救提醒，若没有另外重建进主提示词，就不会传给模型。
OpenAI 兼容渠道没有同样的过滤行为。

修复：保持第一条指令单独发送，把已经按玩家隔离的历史系统消息作为
“本人收到的历史系统记录”传入原生会话；不修改存储内容，也不从其他玩家读取记忆。

验证：拦截真实 callAI 最终序列化请求，用本地响应替代模型。
三种渠道 × 两种视角 × 中英文客户端均保留本人授权记录，不包含他人的私密标记。
这是“该知道的记录可能没传到”，不是发现原生模型能偷看别人。
不能据此断言用户旧对局里每个错误都由该问题造成。

### 2. 狼队纠正被截断、提议被包装成策略

原实现把每条密谈截到前 120 字写入 wolfStrategyLog；
中文系统提示取同夜最后一条，英文取第一条；
生成的 system 记忆还会覆盖同夜上一条摘要。
队友在长发言末尾给出的反驳或纠正，因此可能被这些摘要丢掉。

修复：

- 优先读取已有 wolfChatHistory 原文，旧存档回退到 wolfStrategyLog；
  额外策略区保留最近四夜的逐条讨论，不把某位发言者当成全队定案。
- 新写入日志不再截取前 120 字。
- 旧自动生成的截断摘要不再进入 API 请求，下一次密谈时从旧记忆中移除。
- 密约只注入一次，标注制定/修订夜次和“预案”性质。
- 私密信息区区分实际行动、反馈与计划，不再把里面的密约也称为“已经做过的事”。
- 狼队讨论取消 140 字目标，允许解释完整条件；投票与技能仍遵守各自选择协议。

未恢复已经在历史版本中丢失且没有原文来源的内容；
也没有重写玩家自己的思考或已公开的历史发言。

### 3. 公开配置排列顺序与隐藏座位相关

角色配置和技能说明按隐藏角色第一次出现的座位插入排列。
交换两个未公开身份的座位，会改变普通玩家收到的角色列表。
它不是直接输出“谁是什么”，但属于不必要的隐蔽信息关联。

修复：公开配置、能力索引、角色说明与英文导出固定排序。
同一公开局面交换隐藏底牌，输出应完全一致。

验证：每份客户端 15 对底牌交换 × 4 个输出入口，共 120 次精确字符串比较。
另跑 API 提示、网页接力、摘要中的查验行动者归属和重复 ID 拒绝测试。

## 推理教学做了什么

新增 reasoning-context.js，集中维护小段共用规则和复核提示，
没有添加新的 buildSystemPrompt 包装层。删除了重复和互相牵制的旧要求。

- 刀中女巫不能撤销同夜已使用的毒；区分当夜与未来收益。
- 目标死亡不等于未使用解药，守救同落可以造成死亡。
- 守卫可自守；公开账本不等于真实账本；边缘位置不等于无人防守。
- 有魔术师时比较换与不换的结果，action 仍是名义刀口。
  自刀可能反制交换，也可能真的牺牲狼，不强制采用某种打法。
- 先算完整夜晚后的胜负，再判断还是否需要安排明天。
- 接受队友纠正后，要更新依赖那个前提的行动理由。
- “已回答但我不接受”不能改写成“没回答”；只改计划一项不等于撤回全部。
- 删除“排除所有好人解释后才允许投票”的绝对门槛。
- 无人对跳要考虑真神已死、或已经没有发言机会，不能仅凭合法账本认证。
- 配合、倒钩、切割与另跳身份均按当前收益判断，不要求必死才允许切割。

新加的争议复核与选刀教学随官方/混合模式启用；
纯净/自定义模式不额外塞入这些官方教学。硬规则在所有模式下保留。
提示不提供未公开的角色存活、实际守护对象或交换对象。

## 对这局的复核边界

- 第三天 Mello 是末置位发言，之后直接投票。Light 没有剩余公开发言机会，
  不能把未能当轮反跳解释为他主动沉默，也不能据此认证 Mello。
- 宫野的女巫对跳发生在安室最后发言之前；当时不能让她提前知道安室的
  真实守护与奶穿反馈。否认用药的伪装可评价风险，不应使用后发信息直接判死。
- 对 Gin 的未来查验流应保留没有改动的第一验；改变第二验不等于撤回第一验。
- 最后一夜若交换 Mello 与服部，刀服部会落到 Mello，自刀则会落到服部；
  没交换时的自刀结果相反。应比较分支，而不是事后要求狼人必然知道交换答案。
- “公开承诺了怎么守/怎么换”不等于实际行动；本次没有强迫好人如实交账。

## 可复现的离线检查

- npm test：44 个测试任务，含既有行动、投票、发言解析、回档、
  隔离、教学、联机、剧本杀、卧底与热更新回归。
- npm run test:reasoning-context:browser：
  - 实际 API / 网页 / 规则导出组装，官方与纯净模式隔离。
  - 120 次隐藏底牌交换不变性检查。
  - 两份客户端各 11 个真实夜间结算场景，另验守卫自守与连守限制。
  - 三种渠道实际请求体中本人的系统反馈与狼队记忆边界。
- npm run test:information-boundaries:browser：
  查验/技能结果仅归行动者，普通玩家不得读取，
  API / 网页 / 摘要入口遇到重复玩家 ID 拒绝生成视角。
- npm run build:www：确认共享脚本打入 APK/热更新所用网页包。
- git diff --check：补丁格式检查。

浏览器测试不下载依赖，使用现有 Playwright 与 Chromium：
新测试通过 PLAYWRIGHT_MODULE_PATH / CHROME_PATH 指定路径；
旧隔离测试通过 PLAYWRIGHT_MODULE / PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH 指定路径。
浏览器测试拦截外网；请求体测试只返回本地固定响应，无真实 API key。

## 仍不能承诺的事

- 模型以后不犯错、总能发现诈跳、一定会自刀或打出精彩操作。
- 从截图里的模型自述反推它当时确实收到了哪些输入。
- 自动修复旧存档中已经公开并被多人引用的泄露内容。
- 仅凭当前测试就证明所有自定义角色组合和所有历史存档都不存在问题。

下一步应在用户同意真实模型费用后，用同一批截断到当时时点的局面做前后盲测：

不以“是否猜中真实狼人”作为唯一评价。
